# PT 3D 시뮬레이션 — Feasibility Spike

물리치료 임상 케이스의 특정 소견(고관절 굴곡–요추 보상, 정적 자세 이상,
피부분절 하이라이트)을 **React + react-three-fiber**로 시각화하는 것이
"vibe coding" 난이도로 가능한지 확인하기 위한 스파이크입니다. 전체 앱 UI나
케이스 진행 로직은 없고, 독립된 데모 4개를 탭으로 전환하며 봅니다.

- 브라우저에서 바로 열기: https://claude.ai/code/artifact/13a0139d-4844-4fd7-b46c-b0bb47e5eb42
  (앱 전체 + 모델을 한 파일에 인라인한 빌드, 외부 요청 없음)
- 기술 스택: React 19 · react-three-fiber 9 · @react-three/drei 10 · three.js 0.185 · Vite 8
- 3D 모델: MakeHuman 기본 인체(CC0) — 저장소에 포함된 변환 스크립트로 생성

## 실행

```bash
npm install
npm run dev              # http://localhost:5173
npm run build            # dist/
npm run build:artifact   # artifact/pt-3d-simulation.html — 단일 HTML(모델 포함 약 2.5 MB)
npm run build:model      # scripts/makehuman/의 CC0 원본(base.obj, default.mhskel, default_weights.mhw) → public/models/MakeHuman.glb
```

## 사전 조사: 무료 리깅 인체 모델

조사 중 확인한 실무적 제약: Quaternius·Kenney(CC0)는 itch.io 로그인/세션이 있어야 받아지고, Sketchfab은 무료 CC0 모델도 계정이 필요합니다.
"라이선스가 자유로운 모델"과 "자동화된 환경에서 받아지는 모델"은 거의 겹치지 않았습니다. MakeHuman은 GitHub 저장소에 CC0 원본 데이터가 그대로 있어 둘 다 만족하는 유일한 후보였고, Blender 없이 Node 스크립트(`scripts/build-makehuman.mjs`, 약 250줄)로 glTF를 만들 수 있었습니다.

### MakeHuman 변환 방식

- `base.obj`(19,158 정점, 단위 dm)에서 `body` 그룹과 안구 헬퍼만 남기고(타이츠·스커트·치아·혀·관절 큐브 등 헬퍼 제거) 미터로 변환, 발바닥을 y=0에 맞춤.
- `default.mhskel`의 관절 정의(정점 인덱스 평균 = 관절 위치)로 163개 본의 계층을 만들고, **모든 본의 휴식 회전을 단위행렬**로 둡니다(위치만 관절 머리). 그래서 본 로컬 축 = 세계 축이고, `rig.js`의 "해부학 축 델타" 방식이 변환 없이 그대로 맞습니다.
- **척추 세분화**: 원본 몸통 본 8개(spine05–01, neck01–03)를 척추뼈 24개로 바꿉니다. 요추 5개는 L5/S1(spine05 머리)부터 T12/L1(spine02 머리)까지 같은 높이로, 흉추 12개는 T12가 가장 길고 T1이 가장 짧도록 비율을 주어 C7/T1(neck01 머리)까지, 경추 7개는 C0/C1(head 머리)까지 나눕니다. 각 본의 머리는 아래 추간판 위치라서 "L4" 회전 = L4–L5 분절 운동입니다. 원래 몸통 본에 걸려 있던 정점 가중치는 합쳐서 정점의 높이에 따라 인접한 두 척추뼈에 선형으로 나눠 주므로, 분절마다 작은 회전을 줘도 피부가 매끄럽게 휩니다. 쇄골·유방 본은 높이에 맞는 흉추(T4, T7)에 다시 붙입니다.
- `default_weights.mhw`에서 정점당 상위 4개 가중치를 정규화해 스킨으로 넣고, 스무스 노멀을 계산합니다.
- 기본 메시가 누드라 정점 색(COLOR_0)으로 상의·반바지 영역을 어둡게 칠해 마네킹처럼 보이게 했습니다(팔·다리·머리는 피부색). 재질에서 `vertexColors`로 곱해집니다.
- three.js GLTFLoader가 노드 이름의 `.`을 제거하므로 본 이름을 파일에서부터 `upperleg01_L`처럼 `_`로 바꿔 두었습니다.

## 임상 케이스 모드 (기본 화면)

앱을 열면 "임상 케이스" 모드로 시작합니다. 케이스 하나를 5단계로 진행하고, 단계마다 3D 장면(포즈·시점·가이드·하이라이트)이 자동으로 세팅됩니다. 사용자는 관찰 후 소견을 선택해 제출하고, 정답 여부와 해설을 본 뒤 다음 단계로 넘어갑니다.

| 단계 | 화면 | 사용자 행동 |
|---|---|---|
| 1 환자 정보 | 나이·직업·주호소·병력·이번 케이스의 목표 | 읽고 "관찰 시작" |
| 2 정적 자세 관찰 | 후면 시점, 추선·어깨선·골반선, "정상 자세와 비교" 토글 | 체간 정렬 / 요추 만곡 소견 선택 → 제출 → 해설 |
| 3 능동 고관절 굴곡 검사 | 측면 시점, "검사 시행"으로 동작 재생, 슬라이더·관절각 표시, "정상 패턴과 비교" | 움직임 패턴 소견 선택 → 제출 → 해설 |
| 4 감각 검사 | 하퇴 확대, 저림 부위(L5) 오버레이 표시/끄기 | 피부분절 선택 → 제출 → 해설 |
| 5 종합 | 소견 일치 수, 선택한 답과 정답 표, 해석과 권장 추가 검사 | "처음부터 다시" 또는 "자유 탐색으로" |

케이스는 `src/cases/case01.js`에 **데이터**(환자 정보, 단계별 장면 프리셋, 질문·선택지·정답, 해설)로 정의되어 있고, `src/case/CaseFlow.jsx`가 이를 읽어 단계 UI를 만듭니다. 새 케이스는 같은 형식의 파일을 추가하면 됩니다. 원래의 데모 4개는 상단 "자유 탐색" 모드에 그대로 있습니다.

## 데모 구성 (자유 탐색 모드)

공통: 캔버스는 앱에서 **하나만** 두고, 탭은 오른쪽 패널과 포즈·카메라 상태만 바꿉니다(WebGL 컨텍스트 재생성 없음, 탭 전환 시 포즈·카메라가 부드럽게 전이). 뷰 왼쪽 위 버튼으로 정면/좌측면/후면/우측면/3/4 시점 전환.

| # | 데모 | 조작 | 기법 |
|---|---|---|---|
| 1 | 기본 뷰어 | 회전·줌(마우스/터치), 시점 프리셋, 모델 정보 | `useGLTF` + `CameraControls` |
| 2 | 고관절 굴곡–요추 보상 (핵심) | 굴곡 진행 슬라이더(0–100), 정상/보상 패턴 토글, **두 패턴 블렌딩 슬라이더**, 반복 재생, 관절각 실시간 표시 | 두 패턴을 각각 t의 함수인 관절각 세트로 정의 → w로 선형 보간 → 부모 분절 해부학 축 기준 델타를 바인드 포즈에 적용. 지지 발은 바닥에 고정(planting) |
| 3 | 정적 자세 | 정상 ↔ "좌측 체간 측방 편위 + 요추 전만 감소" 토글, 가이드 라인(추선·어깨선·골반선) | 관절각 상수 두 벌 + 같은 평활 보간. 기본 시점은 후면(치료사 시점) |
| 4 | 부위 하이라이트 (L5) | 표면 오버레이 / 데칼 / 끄기 전환 | 오버레이: skin weight + 바인드 위치로 정점 마스크를 계산해 두 번째 SkinnedMesh(정점 RGBA)로 그림. 데칼: 뼈에 붙인 캡슐·상자 |

### 데모 2의 포즈 정의 (src/three/poses.js)

선 자세에서 왼쪽 무릎 들기(개방 사슬 고관절 굴곡). 두 패턴 모두 대퇴는 같은 높이(최대 95°)까지 올라갑니다.

- 정상: 고관절 굴곡 = 95°·t, 골반·요추 0°
- 보상: 골반 후방경사 25°·s(t), 요추 굴곡 32°·s(t)(s는 초반부터 오르는 smoothstep → "요추가 먼저 굴곡되기 시작"), 고관절 굴곡 = 95°·t − 후방경사 → t=1에서 70°. 흉추·경추는 소폭 신전해 시선을 유지. 지지(오른쪽) 다리는 후방경사만큼 고관절 신전으로 역보정해 수직 유지.
- 블렌딩 w: 두 패턴의 관절각을 선형 보간 — 슬라이더 하나로 "경도 보상"도 만들 수 있음.
- 분절 배분: 요추 굴곡 32°는 L5–S1부터 L1–L2까지 24/24/20/17/15%로 나눠 각 척추뼈 본에 줍니다. 비율은 `poses.js`의 `SEGMENT_W` 한 곳에서 바꿀 수 있습니다.

## 결과 리포트

### 1) 데모별로 쉬웠던 것 / 어려웠던 것

| 데모 | 쉬웠던 것 | 어려웠던 것 |
|---|---|---|
| 1 뷰어 | 로드·회전·줌·터치는 drei가 다 해줌(코드 30줄) | 없음. 단 A-pose 바인드라 "환자처럼 서 있는" 기본 자세는 코드로 만들어야 함(어깨 34° 내림, 팔꿈치 34° 폄). MakeHuman은 glTF를 직접 주지 않아 변환 스크립트가 필요했음(반나절) |
| 2 포즈 블렌딩 | **블렌딩 자체는 쉬움.** 관절각을 숫자로 정의하고 선형 보간 + 쿼터니언 곱 60줄이면 끝. 슬라이더·토글·자동 재생·각도 표시까지 반나절 | (a) **축과 부호**: "굴곡"이 어느 축·어느 부호인지는 리그마다 다르고, 세 번째 모델에서야 "부모 분절의 바인드 프레임에서 세계축 기준으로 정의하고 `P⁻¹·D·P·L`로 변환"하는 일반해를 세움. 이걸로 하면 표에서 유도한 부호가 그대로 맞고 시행착오가 사라짐. (b) **지지 발이 미끄러지는 문제**: 골반을 돌리면 다리도 같이 돌아가므로 지지 다리 역회전 + 발 위치 고정이 필요. 이건 "포즈"가 아니라 "간이 IK"에 해당하는 추가 작업. (c) 임상적 각도는 그대로 넣으면 화면에서 잘 안 보여 데모용으로는 조금 과장이 필요 |
| 3 정적 자세 | 데모 2 인프라 재사용, 관절각 상수만 추가. 가이드 라인 40줄 | "측방 편위(list)"를 단순 기울임이 아니라 몸통 이동으로 만들려면 요추 측굴을 흉추·경추가 반대로 상쇄해야 한다는 걸 직접 각도로 설계해야 함 |
| 4 하이라이트 | **데칼(뼈에 붙인 프리미티브)은 15줄**. 오버레이도 60줄 | 오버레이의 좌표계: 스킨 메시의 정점 데이터가 메시 노드의 로컬(cm)이 아니라 바인드/월드(m) 공간이라 처음엔 마스크가 전부 0이 됨. 좌표계를 맞추자 바로 해결. 결론은 **오버레이가 압도적으로 낫고**, 텍스처 편집은 필요 없었음 |

포즈 블렌딩에 대한 답: 리깅된 glTF에서 **본 트랜스폼 보간 방식은 "실제로 가능"하고 손도 많이 가지 않습니다.** 손이 가는 곳은 블렌딩이 아니라 (1) 리그의 축 컨벤션, (2) 발 고정 같은 물리적 제약, (3) 임상적으로 설득력 있는 각도 설계입니다.

### 2) 3D 모델 라이선스·비용

- 사용 모델: MakeHuman 기본 인체 — **CC0**, 비용 0원. 원본(`scripts/makehuman/`)과 변환본(`public/models/MakeHuman.glb`)을 저장소에 그대로 포함해도 라이선스 문제가 없고, 공개 저장소 전환도 자유롭습니다. 출처 표기는 의무가 아니지만 뷰포트와 이 문서에 넣어뒀습니다.
- 대안: CesiumMan(CC BY 4.0, 출처 표기), VRoid 샘플(CC0, 옷 때문에 부적합), Mixamo(무료지만 원본 재배포 금지). 사실적인 인체(피부·근육)가 필요해지면 Renderpeople/TurboSquid 류 유료 모델(건당 수십~수백 달러) 또는 자체 제작. MakeHuman 앱 자체로 체형(성별·나이·체중·키)을 바꾼 메시를 다시 뽑아 같은 스크립트로 변환하면 케이스별 환자 체형도 무료로 만들 수 있습니다(스켈레톤·가중치는 공통).

### 3) 모바일 브라우저 성능·로딩

- 모델 0.8 MB(텍스처 없음), 삼각형 약 27k, 본 179개 — 스마트폰 GPU에 부담 없는 수준. 첫 로드 후에는 브라우저 캐시. 본이 많아 스킨 행렬은 본 텍스처로 올라가지만(three.js 자동) 성능 영향은 미미.
- JS 번들 약 1.2 MB(gzip 약 330 KB): three.js + r3f + drei + camera-controls. 케이스별 코드 스플리팅으로 더 줄일 수 있음.
- 터치: iPhone 13 에뮬레이션에서 CDP 레벨 실제 터치 이벤트로 한 손가락 회전 확인. 두 손가락 핀치/이동은 camera-controls 기본 동작(에뮬레이터 한계로 실기기 확인 권장).
- 레이아웃: 860px 이하에서 뷰(52vh) 위, 패널 아래로 스택. `dpr` 상한 1.75로 고해상도 폰의 픽셀 수를 제한.
- 이전 버전의 실패 원인이던 "개발 모드 WebGL Context Lost"는 (1) 15 MB 모델 → 0.8 MB, (2) 캔버스 1개 유지, (3) StrictMode 이중 마운트 제거로 재현되지 않음. 만약을 위해 `webglcontextlost`에 `preventDefault`(브라우저 복구 허용)와 안내 배너, 에러 바운더리를 넣었습니다.
- 실기기 FPS·발열은 이 환경(GPU 없는 컨테이너, 소프트웨어 렌더링)에서 측정 불가 — 실기기 테스트 필요.

### 4) 케이스를 여러 개로 확장할 때 필요한 인프라

1. **포즈 정의를 데이터로**: 지금은 `poses.js`에 관절각 함수/상수가 코드로 있습니다. 케이스가 늘면 `{ joint, axis, degrees }` JSON(케이스별 파일) + 검증 스키마로 분리하고, 치료사가 숫자를 직접 조정할 수 있는 간단한 편집 UI(슬라이더 몇 개)를 붙이는 것이 가장 효율적입니다. 이번에 만든 관절 헬퍼(`J.hipFlex(30)` 같은 해부학 어휘)가 그 JSON의 어휘가 됩니다.
2. **애니메이션 파이프라인**: 여러 프레임의 동작(보행 등)은 코드로 각도를 쓰기보다 Blender에서 만든 glTF 클립을 `AnimationMixer`로 재생/크로스페이드하는 것이 맞습니다. MakeHuman 기본 스켈레톤은 MakeHuman의 Blender 플러그인(MPFB)과 호환되므로, Blender에서 같은 리그에 애니메이션을 입혀 glTF로 내보내면 됩니다(단, 이 변환본은 휴식 회전을 단위행렬로 두었으므로 Blender 클립을 쓰려면 변환 스크립트에서 본 방향을 Blender와 같게 맞추거나, 클립을 이 리그 기준으로 다시 굽는 단계가 필요).
3. **리그 컨벤션 고정**: 모델을 바꾸면 축·부호·단위(cm/m)·정점 공간을 다시 확인해야 합니다(이번에 네 번 겪음). 이번 변환은 "모든 본 휴식 회전 = 단위행렬, 단위 m, 정면 +Z, 왼쪽 +X"로 고정했으므로 `rig.js`의 헬퍼 부호가 그대로 맞았고, `B`의 본 이름표만 바꾸면 됐습니다. 체형이 다른 MakeHuman 메시를 추가할 때도 같은 스크립트를 쓰면 이 컨벤션이 유지됩니다.
4. **간이 IK/제약**: 발 고정, 시선 유지 같은 것은 케이스마다 반복됩니다. 지금의 planting을 일반화한 "고정점" 제약 몇 개(양발, 한 발, 손)면 대부분의 임상 자세를 커버합니다.
5. **하이라이트 데이터화**: 피부분절·근육·관절 영역을 "뼈 + 각도 창 + 높이 창" 파라미터로 JSON화하면 오버레이 코드는 그대로 재사용됩니다. 진짜 정밀한 경계가 필요하면 그때 UV 텍스처 마스크로 전환.
6. **에셋 관리·성능**: 모델을 CDN에 두고 버전 관리, 케이스별 lazy import, 필요 시 Draco/Meshopt 압축.
7. **QA**: 이번 스파이크에서 쓴 Playwright 스크린샷 검증(각 데모·시점·슬라이더 값)을 CI에 넣으면 리그·라이브러리 업데이트로 자세가 깨지는 것을 자동으로 잡을 수 있습니다.

## 이전 시도에서 배운 것

- **v1 (CesiumMan)**: 기법은 통했지만 모델이 테스트 더미라 임상 룩이 아니었음.
- **v2 (VRoid 아바타)**: 리그는 좋았지만 드레스가 골반·요추를 가려 핵심 데모가 보이지 않았고, 15 MB 텍스처로 개발 모드에서 WebGL 컨텍스트가 죽었으며, 기본 카메라가 정면이라 시상면 동작이 보이지 않았음. 또 `useGLTF` 캐시 때문에 탭들이 같은 스켈레톤을 공유해 포즈가 탭 간에 누적되는 버그가 있었음.
- **v3 (Mixamo X Bot)**: 옷 없는 마네킹 + 캔버스 1개 + 매 프레임 바인드 포즈에서 재계산 + 해부학 축 기반 관절 정의 + 데모별 임상 시점(측면/후면) + 발 고정. 위 문제가 전부 사라졌습니다.
- **v4**: 임상 케이스 흐름(5단계, 소견 제출·해설·종합)을 기본 모드로 추가.
- **v5 (MakeHuman)**: 척추 3분절 → 5분절(+경추 3분절)로 세분화된 CC0 모델로 교체. 라이선스 이슈가 없어지고 파일이 2.9 MB → 0.8 MB로 줄었으며, 요추 굴곡·측굴이 분절별로 나뉘어 허리가 더 자연스럽게 둥글어집니다. 대신 애니메이션 클립이 없어 데모 1의 클립 재생은 제거했습니다.
- **v6 (현재)**: 척추를 척추뼈 단위 24분절로 세분화. 부위별 각도(예: 요추 굴곡 32°)를 분절 운동 범위 비율대로 나눕니다. 요추 굴곡·신전은 L4–5·L5–S1에 많이, 요추 측굴은 L2–4에 많이, 경추는 C4–6에 많이 배분하고 흉추는 고르게 배분합니다. 뷰 위쪽 "척추 분절" 버튼으로 척추뼈 위치를 몸을 투과해 볼 수 있습니다.
