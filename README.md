# PT 3D 시뮬레이션 — Feasibility Spike

물리치료 임상 케이스의 특정 소견(고관절 굴곡–요추 보상, 정적 자세 이상,
피부분절 하이라이트)을 **React + react-three-fiber**로 시각화하는 것이
"vibe coding" 난이도로 가능한지 확인하기 위한 스파이크입니다. 전체 앱 UI나
케이스 진행 로직은 없고, 독립된 데모 4개를 탭으로 전환하며 봅니다.

- 브라우저에서 바로 열기: https://claude.ai/code/artifact/13a0139d-4844-4fd7-b46c-b0bb47e5eb42
  (앱 전체 + 모델을 한 파일에 인라인한 빌드, 외부 요청 없음)
- 기술 스택: React 19 · react-three-fiber 9 · @react-three/drei 10 · three.js 0.185 · Vite 8

## 실행

```bash
npm install
npm run dev              # http://localhost:5173
npm run build            # dist/
npm run build:artifact   # artifact/pt-3d-simulation.html — 단일 HTML(모델 포함 약 5 MB)
```

## 데모 구성

공통: 캔버스는 앱에서 **하나만** 두고, 탭은 오른쪽 패널과 포즈·카메라 상태만 바꿉니다(WebGL 컨텍스트 재생성 없음, 탭 전환 시 포즈·카메라가 부드럽게 전이). 뷰 왼쪽 위 버튼으로 정면/좌측면/후면/우측면/3/4 시점 전환.

| # | 데모 | 조작 | 기법 |
|---|---|---|---|
| 1 | 기본 뷰어 | 회전·줌(마우스/터치), 시점 프리셋, Mixamo 클립(idle/walk/run) 재생 | `useGLTF` + `CameraControls`; 클립은 `useAnimations`(AnimationMixer) |
| 2 | 고관절 굴곡–요추 보상 (핵심) | 굴곡 진행 슬라이더(0–100), 정상/보상 패턴 토글, **두 패턴 블렌딩 슬라이더**, 반복 재생, 관절각 실시간 표시 | 두 패턴을 각각 t의 함수인 관절각 세트로 정의 → w로 선형 보간 → 부모 분절 해부학 축 기준 델타를 바인드 포즈에 적용. 지지 발은 바닥에 고정(planting) |
| 3 | 정적 자세 | 정상 ↔ "좌측 체간 측방 편위 + 요추 전만 감소" 토글, 가이드 라인(추선·어깨선·골반선) | 관절각 상수 두 벌 + 같은 평활 보간. 기본 시점은 후면(치료사 시점) |
| 4 | 부위 하이라이트 (L5) | 표면 오버레이 / 데칼 / 끄기 전환 | 오버레이: skin weight + 바인드 위치로 정점 마스크를 계산해 두 번째 SkinnedMesh(정점 RGBA)로 그림. 데칼: 뼈에 붙인 캡슐·상자 |

### 데모 2의 포즈 정의 (src/three/poses.js)

선 자세에서 왼쪽 무릎 들기(개방 사슬 고관절 굴곡). 두 패턴 모두 대퇴는 같은 높이(최대 95°)까지 올라갑니다.

- 정상: 고관절 굴곡 = 95°·t, 골반·요추 0°
- 보상: 골반 후방경사 25°·s(t), 요추 굴곡 32°·s(t)(s는 초반부터 오르는 smoothstep → "요추가 먼저 굴곡되기 시작"), 고관절 굴곡 = 95°·t − 후방경사 → t=1에서 70°. 흉추·경추는 소폭 신전해 시선을 유지. 지지(오른쪽) 다리는 후방경사만큼 고관절 신전으로 역보정해 수직 유지.
- 블렌딩 w: 두 패턴의 관절각을 선형 보간 — 슬라이더 하나로 "경도 보상"도 만들 수 있음.

## 결과 리포트

### 1) 데모별로 쉬웠던 것 / 어려웠던 것

| 데모 | 쉬웠던 것 | 어려웠던 것 |
|---|---|---|
| 1 뷰어 | 로드·회전·줌·터치는 drei가 다 해줌(코드 30줄). 클립 재생도 `useAnimations` 한 줄 | 없음. 단 T-pose 바인드라 "환자처럼 서 있는" 기본 자세는 코드로 만들어야 함(어깨 72° 내림) |
| 2 포즈 블렌딩 | **블렌딩 자체는 쉬움.** 관절각을 숫자로 정의하고 선형 보간 + 쿼터니언 곱 60줄이면 끝. 슬라이더·토글·자동 재생·각도 표시까지 반나절 | (a) **축과 부호**: "굴곡"이 어느 축·어느 부호인지는 리그마다 다르고, 세 번째 모델에서야 "부모 분절의 바인드 프레임에서 세계축 기준으로 정의하고 `P⁻¹·D·P·L`로 변환"하는 일반해를 세움. 이걸로 하면 표에서 유도한 부호가 그대로 맞고 시행착오가 사라짐. (b) **지지 발이 미끄러지는 문제**: 골반을 돌리면 다리도 같이 돌아가므로 지지 다리 역회전 + 발 위치 고정이 필요. 이건 "포즈"가 아니라 "간이 IK"에 해당하는 추가 작업. (c) 임상적 각도는 그대로 넣으면 화면에서 잘 안 보여 데모용으로는 조금 과장이 필요 |
| 3 정적 자세 | 데모 2 인프라 재사용, 관절각 상수만 추가. 가이드 라인 40줄 | "측방 편위(list)"를 단순 기울임이 아니라 몸통 이동으로 만들려면 요추 측굴을 흉추·경추가 반대로 상쇄해야 한다는 걸 직접 각도로 설계해야 함 |
| 4 하이라이트 | **데칼(뼈에 붙인 프리미티브)은 15줄**. 오버레이도 60줄 | 오버레이의 좌표계: 스킨 메시의 정점 데이터가 메시 노드의 로컬(cm)이 아니라 바인드/월드(m) 공간이라 처음엔 마스크가 전부 0이 됨. 좌표계를 맞추자 바로 해결. 결론은 **오버레이가 압도적으로 낫고**, 텍스처 편집은 필요 없었음 |

포즈 블렌딩에 대한 답: 리깅된 glTF에서 **본 트랜스폼 보간 방식은 "실제로 가능"하고 손도 많이 가지 않습니다.** 손이 가는 곳은 블렌딩이 아니라 (1) 리그의 축 컨벤션, (2) 발 고정 같은 물리적 제약, (3) 임상적으로 설득력 있는 각도 설계입니다.

### 2) 3D 모델 라이선스·비용

- 사용 모델: Mixamo X Bot — 비용 0원. 앱 안에 포함해 배포 가능, 원본 파일 단독 재배포·판매만 금지. 출처 표기는 의무는 아니지만 뷰포트와 이 문서에 넣어뒀습니다.
- 대안: CesiumMan(CC BY 4.0, 출처 표기), VRoid 샘플(CC0). 모두 무료. 사실적인 인체(피부·근육)가 필요해지면 Renderpeople/TurboSquid 류 유료 모델(건당 수십~수백 달러) 또는 자체 제작.
- 주의: 이 저장소는 Mixamo 원본을 `public/models/Xbot.glb`로 포함합니다. 공개 저장소로 전환한다면 "에셋 재배포"로 읽힐 수 있어, 배포 아티팩트에만 포함하거나 각자 mixamo.com에서 받도록 안내하는 편이 안전합니다.

### 3) 모바일 브라우저 성능·로딩

- 모델 2.9 MB(텍스처 없음), 삼각형 약 49k, 본 67개 — 스마트폰 GPU에 부담 없는 수준. 첫 로드 후에는 브라우저 캐시.
- JS 번들 약 1.2 MB(gzip 약 330 KB): three.js + r3f + drei + camera-controls. 케이스별 코드 스플리팅으로 더 줄일 수 있음.
- 터치: iPhone 13 에뮬레이션에서 CDP 레벨 실제 터치 이벤트로 한 손가락 회전 확인. 두 손가락 핀치/이동은 camera-controls 기본 동작(에뮬레이터 한계로 실기기 확인 권장).
- 레이아웃: 860px 이하에서 뷰(52vh) 위, 패널 아래로 스택. `dpr` 상한 1.75로 고해상도 폰의 픽셀 수를 제한.
- 이전 버전의 실패 원인이던 "개발 모드 WebGL Context Lost"는 (1) 15 MB 모델 → 2.9 MB, (2) 캔버스 1개 유지, (3) StrictMode 이중 마운트 제거로 재현되지 않음. 만약을 위해 `webglcontextlost`에 `preventDefault`(브라우저 복구 허용)와 안내 배너, 에러 바운더리를 넣었습니다.
- 실기기 FPS·발열은 이 환경(GPU 없는 컨테이너, 소프트웨어 렌더링)에서 측정 불가 — 실기기 테스트 필요.

### 4) 케이스를 여러 개로 확장할 때 필요한 인프라

1. **포즈 정의를 데이터로**: 지금은 `poses.js`에 관절각 함수/상수가 코드로 있습니다. 케이스가 늘면 `{ joint, axis, degrees }` JSON(케이스별 파일) + 검증 스키마로 분리하고, 치료사가 숫자를 직접 조정할 수 있는 간단한 편집 UI(슬라이더 몇 개)를 붙이는 것이 가장 효율적입니다. 이번에 만든 관절 헬퍼(`J.hipFlex(30)` 같은 해부학 어휘)가 그 JSON의 어휘가 됩니다.
2. **애니메이션 파이프라인**: 여러 프레임의 동작(보행 등)은 코드로 각도를 쓰기보다 Blender에서 만든 glTF 클립을 `AnimationMixer`로 재생/크로스페이드하는 것이 맞습니다. Mixamo 리그는 Blender·Mixamo 자체 클립과 그대로 호환되므로 이 모델을 유지하면 파이프라인 비용이 가장 낮습니다.
3. **리그 컨벤션 고정**: 모델을 바꾸면 축·부호·단위(cm/m)·정점 공간을 다시 확인해야 합니다(이번에 세 번 겪음). Mixamo 리그로 고정하고 `rig.js`의 헬퍼를 유일한 진입점으로 두세요.
4. **간이 IK/제약**: 발 고정, 시선 유지 같은 것은 케이스마다 반복됩니다. 지금의 planting을 일반화한 "고정점" 제약 몇 개(양발, 한 발, 손)면 대부분의 임상 자세를 커버합니다.
5. **하이라이트 데이터화**: 피부분절·근육·관절 영역을 "뼈 + 각도 창 + 높이 창" 파라미터로 JSON화하면 오버레이 코드는 그대로 재사용됩니다. 진짜 정밀한 경계가 필요하면 그때 UV 텍스처 마스크로 전환.
6. **에셋 관리·성능**: 모델을 CDN에 두고 버전 관리, 케이스별 lazy import, 필요 시 Draco/Meshopt 압축.
7. **QA**: 이번 스파이크에서 쓴 Playwright 스크린샷 검증(각 데모·시점·슬라이더 값)을 CI에 넣으면 리그·라이브러리 업데이트로 자세가 깨지는 것을 자동으로 잡을 수 있습니다.

## 이전 시도에서 배운 것

- **v1 (CesiumMan)**: 기법은 통했지만 모델이 테스트 더미라 임상 룩이 아니었음.
- **v2 (VRoid 아바타)**: 리그는 좋았지만 드레스가 골반·요추를 가려 핵심 데모가 보이지 않았고, 15 MB 텍스처로 개발 모드에서 WebGL 컨텍스트가 죽었으며, 기본 카메라가 정면이라 시상면 동작이 보이지 않았음. 또 `useGLTF` 캐시 때문에 탭들이 같은 스켈레톤을 공유해 포즈가 탭 간에 누적되는 버그가 있었음.
- **v3 (현재)**: 옷 없는 마네킹 + 캔버스 1개 + 매 프레임 바인드 포즈에서 재계산 + 해부학 축 기반 관절 정의 + 데모별 임상 시점(측면/후면) + 발 고정. 위 문제가 전부 사라졌습니다.
