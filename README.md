# PT 3D 시각화 Feasibility Spike

물리치료 임상 케이스의 특정 소견(고관절-요추 보상 패턴, 정적 자세 이상,
피부분절 하이라이트)을 React + react-three-fiber로 시각화하는 것이
vibe coding 난이도로 가능한지 확인하기 위한 스파이크입니다. 프로덕션
UI나 케이스 진행 로직은 포함하지 않으며, 독립된 데모 4개만 탭으로
전환하며 볼 수 있습니다.

## 실행

```bash
npm install
npm run dev
```

개발 모드(`npm run dev`)에서는 React StrictMode가 첫 렌더를 의도적으로
두 번 마운트하는데, 이 프로젝트가 쓰는 모델처럼 텍스처가 많은 무거운
glTF를 소프트웨어 렌더링(GPU 없는 헤드리스 환경 등) 위에서 로드할 때
드물게 `WebGLRenderer: Context Lost`가 뜰 수 있습니다. 프로덕션
빌드(`npm run build && npm run preview`)에서는 재현되지 않았습니다 —
실제 사용자 브라우저(GPU 하드웨어 가속)에서도 발생하지 않을 가능성이
높습니다.

## 리깅 모델: 두 차례 교체한 이유

### 1차: CesiumMan → 2차: Mixamo 수준 리그로 교체 요청

처음에는 로그인 없이 스크립트로 받을 수 있다는 이유로 **CesiumMan**
(KhronosGroup/glTF-Sample-Assets, CC BY 4.0)을 썼습니다. 이후 "리깅
모델을 Mixamo 수준으로 하자"는 요청에 따라 더 상세한 스켈레톤을
조사했고, 아래 표와 같은 벽에 부딪혔습니다.

| 후보 | 라이선스 | 스크립트로 받을 수 있는가 |
|---|---|---|
| **Mixamo 캐릭터** (Adobe) | 상업/비상업 무제한 무료, 단 원본 에셋 재배포는 금지 | ❌ Adobe 계정 로그인 필요, FBX만 제공(glTF 아님) — 헤드리스 세션에서 불가 |
| **Quaternius Universal Base Characters** | CC0 | ❌ itch.io 다운로드가 CSRF 토큰 기반 세션 플로우라 고정 URL로 curl 불가 |
| **Kenney.nl 리깅 캐릭터** | CC0 | ❌ 리깅된 캐릭터는 GitHub 미러에 없고 kenney.nl/itch.io 직접 다운로드만 가능 |
| **Sketchfab CC0/CC-BY 모델** | 다양함 | ❌ 무료 모델도 계정 로그인 필수(공식 정책) |

즉 "라이선스는 자유롭지만 실제로는 브라우저 로그인이 있어야 받아지는"
모델들뿐이었습니다. 이 시점에 방향을 틀어 **VRM 포맷**(VRoid/VirtualCast
생태계에서 쓰는 아바타 표준, glTF 위에 얹은 확장)을 조사했습니다. VRM
스펙은 `humanoid` 본 매핑을 강제하는데, 이게 Mixamo의 Hips/Spine/
Spine1/Spine2/Neck 체계와 동급이거나 더 상세하고, 라이선스 조건이 파일
자체의 JSON 메타데이터에 기계가 읽을 수 있는 형태로 박혀 있어서
외부 페이지를 찾아볼 필요조차 없었습니다.

### 2차 시도: Seed-san → 최종: Victoria Rubin

GitHub(`madjin/vrm-samples`)에 CC0/VRM Public License로 공개된 VRoid
샘플 아바타들을 발견해 `raw.githubusercontent.com`으로 바로 받았습니다
(로그인 불필요, git 프로토콜 자체는 허용된 도메인이라 가능했습니다).

1. **Seed-san** (VirtualCast, Inc. 마스코트)을 먼저 시도했습니다 —
   VRM 1.0 스펙, `hips/spine/chest/neck/head` + 전체 팔다리 체인,
   라이선스는 `VRM Public License 1.0`(재배포·수정·상업적 사용 모두
   허용, 단 출처 표기 필수 — 파일에 박힌 메타데이터로 확인). 그런데
   실제로 로드해보니 **왼팔이 1.3m짜리 로봇 팔로 되어 있는 캐릭터**였습니다
   (VirtualCast 마스코트 고유 디자인). 리그 자체는 훌륭했지만 임상
   시각화용 "일반적인 사람 몸"으로는 전혀 맞지 않아 폐기했습니다.
2. **Victoria Rubin** (VRoid Studio 베타 샘플 아바타)으로 최종 교체 —
   **CC0**(출처 표기조차 불필요, Seed-san보다 더 자유로운 라이선스),
   `J_Bip_C_Hips/Spine/Chest/UpperChest/Neck/Head` + 좌우 다리
   전체 체인 + 손가락까지 포함된 표준 VRoid 리그(스펙상 Mixamo와
   동급이거나 그 이상 — Chest/UpperChest 2단으로 Mixamo의
   Spine1/Spine2보다 오히려 더 세분화됨), 로봇 팔 같은 특이 부위 없이
   일반적인 사람 체형. 최종적으로 이 모델을 채택했습니다.

이 과정에서 배운 것: **"라이선스가 자유로운 리깅 인체 모델"과
"실제로 자동화된 파이프라인에서 받을 수 있는 모델"은 거의 겹치지
않습니다.** VRM 생태계(특히 GitHub에 미러링된 샘플들)가 이 세션에서
찾은 유일한 예외였습니다. 또한 캐릭터의 실제 디자인(로봇 팔처럼)을
라이선스 문서만 보고는 알 수 없으므로, 렌더링해서 눈으로 확인하는
단계가 반드시 필요했습니다.

### 최종 사용 모델

**"Victoria Rubin"** (VRoid Studio 샘플 아바타) — **CC0**(퍼블릭
도메인 수준, 출처 표기 불필요). `public/models/VictoriaRubin.glb`
(15.5MB, 텍스처 28장 포함). 출처: https://github.com/madjin/vrm-samples

## 데모 구성

- **데모 1 · 기본 뷰어** (`src/demos/Demo1Viewer.jsx`) — 모델 로드 + `OrbitControls`. 데스크톱 드래그/휠, 모바일 터치 드래그/핀치는 three.js 기본 매핑 그대로 사용.
- **데모 2 · 고관절 굴곡-요추 보상 패턴** (`src/demos/Demo2HipLumbar.jsx`) — 슬라이더 하나가 (a) 굴곡 진행도, (b) 정상↔보상 포즈 블렌드 가중치를 동시에 제어. `THREE.Quaternion.slerp`로 본별 델타 회전을 보간(`src/three/bonePose.js`).
- **데모 3 · 정적 자세 하이라이트** (`src/demos/Demo3StaticPosture.jsx`) — "좌측 체간 측방 편위 + 요추 전만 감소" 고정 포즈 vs 정상 포즈, 토글 버튼 + 스프링 보간 전환.
- **데모 4 · 신체 부위 하이라이트** (`src/demos/Demo4Dermatome.jsx`) — 좌측 종아리 외측~발등(L5 피부분절 근사)을 반투명 데칼 메시로 표시. 메시는 `bone.add(mesh)`로 기존 스켈레톤 본에 직접 자식으로 붙여 포즈 변화에도 함께 움직임.

본 이름 매핑은 `src/three/bonePose.js`의 `BONES` 상수 하나에 모여있어서, 모델을 바꿀 때 이 파일만 고치면 됩니다(실제로 CesiumMan → Seed-san → Victoria Rubin 세 번 교체하면서 이 구조 덕에 데모 코드 자체는 거의 손대지 않았습니다).

## 결과 리포트

### 1) 데모별 난이도

| 데모 | 쉬웠던 점 | 어려웠던 점 |
|---|---|---|
| 1. 기본 뷰어 | `useGLTF` + `<primitive object={scene}/>` + drei `OrbitControls`로 15분 내 완성. 터치 지원은 코드 추가 없이 기본 제공(Playwright로 CDP 레벨 실제 터치 이벤트를 시뮬레이션해 확인) | drei `<Environment preset="city">`가 외부 CDN에서 HDRI를 fetch하다 네트워크 정책에 막혀 앱 전체가 에러 바운더리 없이 죽는 문제 — 제거하고 기본 조명만 사용 |
| 2. 고관절-요추 보상 (가장 중요) | **포즈 블렌딩 자체는 세 모델 모두에서 예상보다 쉬웠음.** 본 이름만 알면 오일러→쿼터니언 변환, bind pose 기준 델타 적용, `slerp` 블렌드까지 순수 함수 60줄로 해결되고, 모델을 갈아끼워도 `BONES` 상수만 바꾸면 나머지 로직은 그대로 재사용됨 | **리그가 바뀔 때마다 축 컨벤션을 처음부터 다시 확인해야 했음.** CesiumMan(Blender 계열, 본에 bind 회전 있음)과 Victoria Rubin(VRoid 표준, 모든 본이 bind 시 identity 회전 — 로컬 축=월드 축)은 컨벤션 자체가 달라서, 같은 각도 값을 넣어도 시각적 결과가 달랐습니다. 매번 스크린샷으로 축/부호를 재검증해야 했음 |
| 3. 정적 자세 | 데모 2와 동일한 유틸(`applyBlendedPose`)을 재사용해 짧게 완성. 토글 시 스프링처럼 부드럽게 보간하는 것도 몇 줄로 추가 가능 | 측방 편위 각도가 리그마다 "육안으로 보이는" 크기가 달랐음(CesiumMan은 14~22°면 보였지만 Victoria Rubin에서는 20°대까지 올려야 확실히 보임) — 진단용으로 극단적인 각도(60°)를 먼저 넣어 축 자체가 맞는지 확인한 뒤 값을 낮추는 방식으로 작업했음 |
| 4. 부위 하이라이트 | 데칼 메시(추가 지오메트리를 본에 자식으로 붙이는 방식)는 UV 지식이 전혀 없어도 되고, 포즈가 바뀌어도 자동으로 따라다녀서 구현이 제일 빨랐음 | 리그가 바뀌면 캡슐/박스의 크기·위치를 처음부터 재조정해야 했고(체형·본 길이가 다르므로), Victoria Rubin은 **신발/스타킹 같은 의상 메시가 발등 하이라이트를 가려버려서** 발 부위는 눈에 안 보이는 채로 남았음 — 스타일라이즈드 아바타는 옷이 진단 표시를 가릴 수 있다는, CesiumMan(맨몸 테스트 더미)에서는 안 보였던 새로운 제약 |

### 2) 3D 모델 라이선스/비용

- **최종 사용 모델**: "Victoria Rubin" (VRoid Studio 샘플) — **CC0**, 비용 없음, 출처 표기조차 불필요.
- Mixamo는 여전히 라이선스 자체는 자유롭지만(재배포 금지 조항만 준수하면 OK), **자동화된 다운로드가 원천적으로 불가능**(Adobe 로그인 필수)해서 이번 스파이크처럼 스크립트로 재현 가능해야 하는 환경에는 부적합 — 사람이 직접 mixamo.com에서 다운로드해 전달하는 흐름이라면 여전히 유효한 후보.
- VRM 생태계는 라이선스 조건이 파일 메타데이터에 기계가 읽을 수 있는 형태로 박혀있어(예: `commercialUsage`, `allowRedistribution`, `licenseName` 필드) 외부 약관 페이지를 뒤질 필요가 없었다는 점이 실무적으로 큰 장점이었습니다.
- 더 사실적인(스타일라이즈드가 아닌) 인체 모델이 필요하면 Renderpeople/Turbosquid 등 유료 상업 라이선스가 필요 — 건당 대략 수십~수백 달러.

### 3) 모바일 브라우저 성능/로딩 이슈

- **OrbitControls 터치 회전은 세 모델 모두 별도 코드 없이 정상 동작**(Chromium iPhone 13 에뮬레이션 + CDP 레벨 실제 터치 이벤트로 확인).
- 프로덕션 JS 번들: 약 1.17MB(gzip 324KB, three.js/r3f/drei 포함) — 모델과 무관하게 고정.
- **모델 파일 크기가 리그 디테일/스타일에 따라 크게 차이남**: CesiumMan 428KB(텍스처 1장) → Victoria Rubin 15.5MB(텍스처 28장). Mixamo 수준의 디테일과 VRoid 특유의 다층 의상 메시를 얻은 대가로 로딩 비용이 36배 커진 셈 — 실제 모바일 회선/저사양 기기에서는 초기 로딩이 눈에 띄게 느릴 것으로 예상됨(이번 세션은 헤드리스 환경이라 실기기 체감 속도는 측정 불가).
- 개발 모드에서 이 무거운 모델을 소프트웨어 렌더링으로 첫 로드할 때 `WebGLRenderer: Context Lost`가 발생(React StrictMode의 이중 마운트 + 텍스처 28장 동시 디코딩이 겹친 것으로 추정) — 프로덕션 빌드에서는 재현 안 됨. 실기기(GPU 가속)에서는 이 문제 자체가 없을 가능성이 높지만, 저사양 기기에서 유사 증상이 있는지 실측 필요.
- 프로덕션에서는 텍스처 해상도 축소 / Draco·Meshopt 압축 / 번들 코드 스플리팅을 권장.

### 4) 케이스 확장 시 필요한 추가 인프라

1. **애니메이션/포즈 파이프라인**: 지금은 본 이름과 회전값을 코드에 하드코딩했음. 케이스가 늘어나면 Blender 등에서 포즈를 만들고 glTF 애니메이션 클립으로 export → three.js `AnimationMixer`로 크로스페이드하는 방식으로 전환하는 게 유지보수에 유리.
2. **리그 축 컨벤션 문서화/표준화 (이번에 가장 크게 체감한 항목)**: 리그를 한 번 더 바꿀 가능성이 있다면, "본 이름 + 축 + 부호 + bind 컨벤션(identity vs. baked rotation)"을 표로 미리 문서화해두는 게 필수. CesiumMan→Seed-san→Victoria Rubin 세 번 모두 이 부분을 스크린샷 시행착오로 다시 알아내야 했습니다.
3. **에셋 관리**: 모델이 리그 디테일 때문에 428KB→15.5MB로 커진 것처럼, 케이스가 늘면 CDN 호스팅 + 버전 관리 + 압축(Draco/Meshopt/텍스처 해상도 축소)이 빠르게 필요해짐.
4. **하이라이트 데이터화 + 의상 충돌 처리**: 데칼 메시 위치/크기를 JSON으로 분리하는 것 외에도, Victoria Rubin에서 겪은 것처럼 "이 리그는 의상이 특정 부위를 가린다"는 제약을 감지·회피하는 로직(예: 해당 의상 메시를 부분 투명 처리)이 스타일라이즈드 아바타를 쓸 경우 추가로 필요.
5. **모델 선정 체크리스트**: 이번 스파이크에서 확인된 실전 체크리스트 — (a) 라이선스가 자유로운가, (b) 로그인 없이 스크립트로 받을 수 있는가, (c) 실제 렌더링했을 때 캐릭터 디자인이 목적에 맞는가(로봇 팔 같은 특이 요소가 없는가), (d) 리그가 필요한 본 세분화를 제공하는가, (e) 의상이 하이라이트 대상 부위를 가리지 않는가. 다섯 가지 모두 통과해야 다음 단계로 넘어갈 수 있었습니다.
6. **QA/검증 도구**: Playwright 스크린샷 회귀 테스트를 CI에 넣어 리그나 라이브러리 버전이 바뀔 때 자세가 깨지는 걸 자동 감지 — 이번 스파이크 내내 수동으로 한 걸 자동화하는 것.

## 결론

**네 가지 데모 모두 "vibe coding" 난이도로 구현 가능했고, 리깅 모델을
세 번(CesiumMan → Seed-san → Victoria Rubin) 교체하면서도 데모 로직
자체는 `BONES` 상수 하나만 바꾸면 재사용됐습니다.** 포즈 블렌딩
(`Quaternion.slerp`)은 리그가 바뀌어도 기술적으로 항상 쉬웠던 반면,
**모델 조달 자체가 가장 큰 병목**이었습니다: 라이선스가 자유로운
모델 대부분이 실제로는 로그인 없이 받을 수 없었고(Mixamo, Quaternius,
Sketchfab, Kenney 전부), VRM 생태계만이 예외였습니다. 게다가 라이선스
문서만으로는 알 수 없는 "캐릭터 실제 디자인"(로봇 팔) 때문에 한 번
더 갈아엎어야 했습니다. 케이스를 여러 개로 확장한다면, 모델 조달
체크리스트를 표준화하고 리그 축 컨벤션을 문서화하는 것이 최우선
과제입니다.
