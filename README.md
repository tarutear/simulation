# PT 3D 시각화 Feasibility Spike

물리치료 임상 케이스의 특정 소견(고관절-요추 보상 패턴, 정적 자세 이상,
피부분절 하이라이트)을 React + react-three-fiber로 시각화하는 것이
vibe coding 난이도로 가능한지 확인하기 위한 스파이크입니다. 프로덕션
UI나 케이스 진행 로직은 포함하지 않으며, 독립된 데모 4개만 탭으로
전환하며 볼 수 있습니다.

## 실행

```bash
npm install
npm run dev
```

## 사전 조사: 무료 리깅 인체 모델 후보

| 모델 | 라이선스 | 특징 |
|---|---|---|
| **CesiumMan** (KhronosGroup/glTF-Sample-Assets) — **이번 스파이크에서 사용** | CC BY 4.0 (© 2017 Cesium) — 출처 표기 조건으로 상업적 사용 포함 자유 이용 | 텍스처+스키닝 완료된 glTF, 19개 조인트(골반/척추 2단/좌우 고관절-무릎-발목). GitHub에서 로그인 없이 직접 다운로드 가능, `raw.githubusercontent.com`이 CORS 허용이라 런타임 fetch도 가능 |
| **Mixamo 캐릭터** (Adobe, 예: X Bot/Y Bot) | Adobe 일반 이용약관: 상업/비상업 무제한 무료 사용 가능하나, **원본 캐릭터/애니메이션 파일 자체를 에셋팩으로 재판매·재배포는 금지**(완성된 프로젝트에 포함시켜 배포하는 것은 허용) | 스켈레톤이 가장 상세(Spine/Spine1/Spine2/Neck 등)해서 정교한 보상 패턴 표현엔 최적. 단, 다운로드에 Adobe 계정 로그인이 필요해 이번 세션(헤드리스 환경)에서는 자동 다운로드 불가 → 실제 프로덕션에서는 유력 후보 |
| **Quaternius Universal Base Characters** | CC0(퍼블릭 도메인 수준, 출처 표기도 불필요) | 완전 무제한 사용 가능. poly.pizza / itch.io에서 수동 다운로드 필요, 로우폴리 스타일이라 임상 시각화용으로는 다소 캐주얼한 룩 |

**결론:** 라이선스 안전성과 "로그인 없이 스크립트로 재현 가능"이라는 스파이크 조건상 CesiumMan을 채택했습니다.
프로덕션에서 더 해부학적으로 사실적인 룩이 필요하면 Mixamo(재배포 금지 조건만 준수) 또는 유료 CC 라이선스 인체 모델(예: Sketchfab의 개별 라이선스 확인된 모델)을 검토 권장.

## 데모 구성

- **데모 1 · 기본 뷰어** (`src/demos/Demo1Viewer.jsx`) — 모델 로드 + `OrbitControls`. 데스크톱 드래그/휠, 모바일 터치 드래그/핀치는 three.js 기본 매핑 그대로 사용.
- **데모 2 · 고관절 굴곡-요추 보상 패턴** (`src/demos/Demo2HipLumbar.jsx`) — 슬라이더 하나가 (a) 굴곡 진행도, (b) 정상↔보상 포즈 블렌드 가중치를 동시에 제어. `THREE.Quaternion.slerp`로 본별 델타 회전을 보간(`src/three/bonePose.js`).
- **데모 3 · 정적 자세 하이라이트** (`src/demos/Demo3StaticPosture.jsx`) — "좌측 체간 측방 편위 + 요추 전만 감소" 고정 포즈 vs 정상 포즈, 토글 버튼 + 스프링 보간 전환.
- **데모 4 · 신체 부위 하이라이트** (`src/demos/Demo4Dermatome.jsx`) — 좌측 종아리 외측~발등(L5 피부분절 근사)을 반투명 데칼 메시로 표시. 메시는 `bone.add(mesh)`로 기존 스켈레톤 본에 직접 자식으로 붙여 포즈 변화에도 함께 움직임.

## 결과 리포트

### 1) 데모별 난이도

| 데모 | 쉬웠던 점 | 어려웠던 점 |
|---|---|---|
| 1. 기본 뷰어 | `useGLTF` + `<primitive object={scene}/>` + drei `OrbitControls`로 15분 내 완성. 터치 지원은 코드 추가 없이 기본 제공 | 없음. drei `<Environment preset="city">`가 외부 CDN(raw.githack.com)에서 HDRI를 fetch하다가 네트워크 정책에 막혀 앱 전체가 에러 바운더리 없이 죽는 문제가 있었음 — 오프라인/제한된 네트워크 환경에서는 `Environment` 프리셋 대신 기본 조명만 쓰는 게 안전 |
| 2. 고관절-요추 보상 (가장 중요) | **포즈 블렌딩 자체는 예상보다 쉬웠음.** 본 이름만 알면(GLB의 JSON 청크를 노드로 파싱해 20분 만에 확인) 오일러→쿼터니언 변환, bind pose 기준 델타 적용, `slerp` 블렌드까지 순수 함수 60줄로 해결. React 상태(슬라이더)를 매 렌더마다 본 쿼터니언에 직접 mutate하는 방식이 매끄럽게 동작 | **회전 축의 부호/방향을 알아내는 게 시행착오였음.** CesiumMan 같은 임의의 리깅 모델은 본의 local axis 컨벤션이 문서화되어 있지 않아, "고관절 굴곡=음의 X축 회전" 같은 걸 값 바꿔가며 스크린샷으로 확인해야 했음. Mixamo처럼 커뮤니티에 축 컨벤션이 잘 알려진 리그를 쓰면 이 단계가 크게 줄어들 것 |
| 3. 정적 자세 | 데모 2와 동일한 유틸(`applyBlendedPose`)을 재사용해 15분 내 완성. `useFrame`으로 토글 시 스프링처럼 부드럽게 보간하는 것도 몇 줄로 추가 가능 | 측방 편위(list) 각도가 처음엔 너무 작아(4~14°) 육안으로 거의 안 보였음 — 임상적으로는 미세한 변화라도, 3D 뷰어에서 "명확히 보이는" 정도로는 실제 각도보다 과장해서 표현할 필요가 있음(스타일라이즈드 vs 정량적 정확성의 트레이드오프) |
| 4. 부위 하이라이트 | 데칼 메시(추가 지오메트리를 본에 자식으로 붙이는 방식)는 UV 지식이 전혀 없어도 되고, 포즈가 바뀌어도 자동으로 따라다녀서 구현이 제일 빨랐음(30분) | 본 로컬 좌표계를 몰라서 캡슐/박스의 위치·크기를 스크린샷 보면서 반복 조정해야 했음. 텍스처 오버레이 방식은 시도조차 하지 않았는데, UV 언랩 좌표를 알아야 하고(에디터에서 확인하거나 UV 좌표를 파싱해야 함) 텍스처를 직접 리페인트하거나 셰이더에서 UV 마스크를 만들어야 해서 스파이크 범위에서는 명백히 더 비쌈 |

### 2) 3D 모델 라이선스/비용

- 사용 모델: **CesiumMan** (glTF Sample Assets, KhronosGroup) — **CC BY 4.0**, 비용 없음, 출처 표기(© Cesium)만 지키면 상업 프로젝트 포함 자유 사용.
- 대안(Mixamo)은 무료지만 "원본 에셋 재배포 금지" 조항 때문에 깃 레포에 raw 캐릭터 파일을 커밋해 배포하는 형태는 법적으로 회색지대 — 프로덕션 결정 전 Adobe 약관 재확인 권장.
- 임상적으로 더 해부학적인(피부/근육 디테일이 있는) 유료 인체 모델이 필요해지면 Sketchfab Pro 라이선스나 Renderpeople/Turbosquid 등 상업 라이선스 구매가 필요 — 건당 대략 수십~수백 달러 수준(가격은 각 마켓플레이스 확인 필요).

### 3) 모바일 브라우저 성능/로딩 이슈

- Chromium(iPhone 13 뷰포트 에뮬레이션) + CDP 레벨 실제 터치 이벤트로 확인한 결과, **OrbitControls의 한 손가락 드래그 회전은 별도 코드 없이 정상 동작**(three.js 기본 터치 매핑).
- 프로덕션 빌드 결과물: JS 번들 약 1.17MB(gzip 324KB) — three.js/r3f/drei를 한 번에 로드하는 단일 청크라 경고가 뜸. 모델 자체는 428KB(glTF-Binary, 텍스처 포함)로 가벼운 편.
- 실기기(저사양 안드로이드 등)에서의 실측 FPS/배터리/발열은 이번 세션(헤드리스 컨테이너, 실제 모바일 GPU 없음)에서 측정 불가 — 실기기 테스트 필요.
- 프로덕션에서는 번들 코드 스플리팅(데모/케이스별 lazy import)과 Draco/Meshopt 압축이 적용된 glTF 사용을 권장.

### 4) 케이스 확장 시 필요한 추가 인프라

1. **애니메이션/포즈 파이프라인**: 지금은 본 이름과 회전값을 코드에 하드코딩했음. 케이스가 늘어나면 (a) Blender 등에서 포즈를 만들고 glTF 애니메이션 클립으로 export → 런타임에서 클립 간 크로스페이드(three.js `AnimationMixer`가 기본 지원)하는 방식으로 전환하는 게 유지보수에 유리. 지금 같은 순수 코드 기반 포즈 정의는 "슬라이더 하나로 미세 조정 가능한 소수 소견"에는 적합하지만, 케이스 수가 늘면 아티스트/애니메이터 협업 도구(Blender 포즈 라이브러리 등)가 필요해짐.
2. **리그 축 컨벤션 문서화/표준화**: 모델을 바꿀 때마다 이번처럼 축 방향을 스크린샷으로 시행착오할 수는 없으므로, 사용할 리그(예: Mixamo 표준)를 하나로 고정하고 본별 "굴곡/신전/측굴 = 어느 축 + 부호"를 내부 매핑 테이블로 문서화해두는 게 필수.
3. **에셋 관리**: 모델·텍스처·애니메이션 클립이 늘어나면 `public/models`에 다 넣는 지금 방식은 금방 무거워짐 → CDN 호스팅 + 버전 관리(예: 케이스별 매니페스트 JSON), Draco/Meshopt 압축, lazy loading 필요.
4. **하이라이트 데이터화**: 지금은 데칼 메시 위치/크기를 코드에 하드코딩했지만, 피부분절/근육/관절 등 하이라이트 대상이 늘어나면 "본 이름 + 로컬 오프셋 + 크기"를 JSON 데이터로 분리하고, 필요하면 실제 UV 마스크 기반 텍스처 오버레이(셰이더 머티리얼)로 전환하는 게 정확도 면에서 유리.
5. **QA/검증 도구**: 포즈·하이라이트가 해부학적으로 올바른지 개발자가 눈으로만 확인하는 지금 방식 대신, 스크린샷 회귀 테스트(Playwright 등)를 CI에 넣어 리그나 라이브러리 버전이 바뀔 때 자세가 깨지는 걸 자동 감지하는 게 좋음(이번 스파이크에서 Playwright로 축 방향을 검증한 것과 동일한 방식).

## 결론

**네 가지 데모 모두 "vibe coding" 난이도로 하루 안에 구현 가능했습니다.** 특히
가장 우려했던 포즈 블렌딩(데모 2)은 리깅된 glTF 모델 + `Quaternion.slerp`
조합으로 예상보다 훨씬 단순하게 해결됐고, 실제 병목은 코드 난이도가 아니라
"본 좌표계 컨벤션을 모르는 상태에서 시행착오로 알아내는 시간"이었습니다.
케이스를 여러 개로 확장한다면 이 부분을 표준화하는 것이 최우선 과제입니다.
